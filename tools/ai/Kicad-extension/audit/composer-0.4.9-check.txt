KiCad 扩展与终端检查说明（0.4.9）

已安装并打开：VS Code 窗口“kicad · 建议与工具参考 0.4.9”。
窗口内已打开聊天和原生 kicad 终端，终端检查模型为 DeepSeek Flash。
终端基于完整 OpenCode 1.19.3，保留原有命令、会话、模型、权限、插件、技能和内嵌 Web 界面。

扩展检查
1. 在输入框输入：“帮我只读检查 U1 和 R1（10 kΩ），不要修改文件，也不要布线，解释发现的问题。”
2. 点魔杖：使用当前选择的模型，在输入框内优化。不弹预览窗，不自动发送；可撤销、取消，自己编辑时不会被旧结果覆盖。
3. 一轮对话完成且输入框为空时，可能出现灰色“下一句建议”。Tab、右箭头、Enter 或接受按钮只填入草稿，之后仍须手动发送。
4. 点“工具参考”可搜索真实 MCP 工具目录。选择只加入工具名、用途和参数，不执行工具。
5. 取消“下一句建议”勾选，可停止后台建议请求；模型认为没有合适下一步时可以不显示建议。

终端检查
- Ctrl+P 打开命令面板，选择“优化提示词（当前模型，不发送）”。同一面板可撤销或取消优化。
- /suggestions 切换下一句建议，/suggest 请求建议；Tab、右箭头、Enter 只接受到草稿，Esc 忽略。
- /tools 打开工具参考目录，选择后只加入草稿，保留已有附件。
- /models 切换模型。也可在系统终端运行：kicad --model kicad-deepseek/deepseek-flash

验证结果
- 终端回归：204 通过、1 跳过、0 失败，523 个断言。
- 扩展 TypeScript/Vue 和终端前后端类型检查通过；安装文件与最终构建包一致。
- 真实 VS Code 宿主确认聊天、设置前端加载，原生终端启动，MCP 和 DeepSeek 配置可用。
- 两端真实 DeepSeek 的独立文本请求成功；本机 MCP 目录读取到 14 个入口，未调用工具、未自动发送聊天消息。
- 本轮使用合成文本对话验证生成逻辑，没有执行实际 PCB 检查或修改设计文件。

OpenCode 托管免费模型可能拒绝辅助生成请求。错误会显示，草稿不会被替换；可选择已配置的 DeepSeek。
