## 问题与修复

截图中的“Code Key”弹窗属于编辑器的系统凭据访问。当前真实用户的默认钥匙串路径和 login.keychain-db 文件均存在；未重置、删除或改写用户钥匙串。检查时截图中的开发窗口已经关闭，真实窗口仍加载旧版 0.4.24。

旧测试启动脚本使用隔离配置/临时 HOME，却没有统一隔离 SecretStorage，且只终止 CLI 包装器，存在触发钥匙串访问和遗留开发窗口的路径。现在五个 SDK 宿主脚本统一使用 vscode-test-host.cjs：独立扩展目录、内存 SecretStorage、移除继承的提供商密钥和编辑器 IPC 环境，直接启动 VS Code 主程序。结束时处理自己的测试进程；若 macOS 不允许进程组信号，则仅终止自己创建的主进程。正常用户启动未使用内存存储参数，保留加密凭据方式。

成品包启动验收脚本也改为拥有独立进程组并等待退出，跳过已结束的进程。扩展构建清单开始纳入 CJS 测试和宿主启动脚本，避免测试代码变化漏出源指纹。
