当前调用链

终端原生插件工具 / 扩展 SDK 进程内工具
  -> tools/ai/direct 中共用的 JS handlers / Runtime.dispatch
  -> KiCad C++ 编辑器的原生 IPC，或原生 kicad-cli 作业

IPC 直接连接持有文档的 C++ 编辑器进程；没有额外 Go、WebSocket 或嘉立创连接器。
布线、扇出、铺铜、原理图生成、流水线、审计与交付证据逻辑放在共用 JS 模块。
导出、DRC/ERC 等原生作业仍调用 KiCad 自己的 CLI。可选外部工具直接启动其原生程序。
扩展的健康检查和工具目录读取也已经改为进程内调用。
轻量旧扩展的动作和可选模型循环同样导入共用模块。

改动与兼容边界

- 删除 tools/ai/kicad-agent 的 Go 源码、测试、生成的 Go protobuf 和旧构建目标。
- 移除原 easyeda-agent 子模块工作目录、连接器构建脚本和活动调用配置。
- 原生构建、终端、主扩展及轻量旧扩展均使用共用 JS 模块。
- 终端在最终配置合并后移除遗留 kicad/easyeda MCP 连接器，保留其他用户配置。
- 主扩展通过 SDK 的进程内 server 接口注册工具，不启动 stdio MCP 路由进程。
  mcp__kicad__ 前缀是 SDK 工具命名形式，不表示存在外部 MCP 子进程。
- 独立 stdio MCP 仅保留给用户显式配置的外部客户端，内置两端不启动它。
- 安装 ID kicad-agent.kicad 和旧状态目录名保留，用于升级与状态兼容。
- 工作区原有 C++ 等并行修改保留，未执行 reset、clean、stash 或提交。
